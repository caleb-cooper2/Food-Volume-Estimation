# Contributing

Thanks for your interest in contributing to this project. We welcome bug reports, feature ideas, documentation improvements, and code changes.

## How to contribute

There are a few good ways to help:

- Report bugs or unexpected behavior
- Suggest improvements or new features
- Improve documentation
- Submit fixes for open issues

## Before you start

- Check the existing issues and pull requests to avoid duplicating work
- Keep changes focused on a single topic or bug
- Prefer small, reviewable pull requests
- Make sure your contribution matches the project’s goals and architecture

## Development setup

1. Fork the repository and clone your fork locally.
2. Create a virtual environment and install dependencies.
3. Install any project-specific tooling required for local development.
4. Run the relevant validation steps before submitting your changes.

Use the project README for the most up-to-date setup and environment details.

## Making changes

- Create a descriptive branch for your work.
- Keep code readable, well-structured, and consistent with the surrounding codebase.
- Avoid unrelated refactoring in the same pull request.
- Document any new configuration, environment variables, or usage patterns.

## Pull requests

When you are ready to submit:

- Open a pull request with a clear title and summary
- Explain what changed and why
- Link any related issues or discussions
- Include screenshots or examples when the change affects behavior
- Make sure the PR is ready for review and not still a work in progress

## Issue reports

When filing an issue, include:

- A clear description of the problem
- Steps to reproduce it
- Expected behavior
- Actual behavior
- Relevant logs, screenshots, or examples when useful

## Code review expectations

Contributors should be respectful, constructive, and focused on improving the project. Review comments should aim to clarify intent, fix issues, and maintain quality.

## Questions

If you are unsure about the best way to contribute, start by opening an issue or asking in the project discussion area. We are happy to help point you in the right direction.

Thank you for helping improve the project.
